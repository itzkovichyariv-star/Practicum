## 1. תקציר מנהלים

המסמך מאפיין שני שינויים משלימים:

| # | נושא | מהות |
|---|------|------|
| **א** | **הפרדת אוכלוסיות** | ברגע שמועמד עבר ראיון הוא הופך לסטודנט ויורד מדף המועמדים. כל תיק המועמדות (טופס הגשה, קורות חיים, סיכום ראיון, ציוני הערכה) עובר איתו ונגיש מדף הסטודנט. רשומת המועמדות **נשמרת בארכיון** ולא נמחקת, כדי לא לאבד סטטיסטיקה והיסטוריה. |
| **ב** | **דף מועמדים עשיר** | שדרוג התצוגה בדף המועמדים לרמת העושר של דף הסטודנטים, כך שטופס המועמדות, קורות החיים, תאריך הראיון והציון נגישים ישירות מהשורה בלי להיכנס לכרטיס. |

שני השינויים תלויים זה בזה: ברגע שהמועמדים "האמיתיים" הם היחידים ברשימה, יש מקום להציג עליהם יותר מידע.

## 2. מצב קיים — ניתוח מדויק

### 2.1 מודל הנתונים

**`DB.candidates[]`** — שדות קיימים:

```
id, name, phone, email, city, courseId, year
applicationDate, preferredArea, notes
file_cv          → {name, originalName, size, uploadDate, folder}
file_application → {name, originalName, size, uploadDate, folder}
interviewDate, interviewResult ('passed'|'failed'|''), interviewSummary
evalCommitment, evalMotivation, evalCommunication, evalEnglish, evalAcquaintance, evalScore
rejectionReason, acceptedDate, manualSummary
status  ← מחושב אוטומטית
```

**`DB.students[]`** — שדות קיימים:

```
id, name, phone, email, city, courseId, year
prepDone, prepDate
acceptedOrg, interviews, hired, preferences[3], submitted[]
hoursReported, hoursApproved, hoursConfirmed, orgFeedback
file_cv, file_form, file_summary, file_feedback
cvUrl, formUrl, summaryUrl
notes, manualSummary, fromCandidate
```

### 2.2 חישוב הסטטוס — `computeCandidateStatus()` (index.html:4373)

```
interviewResult === 'failed'                    → 'rejected'
interviewResult === 'passed'                    → 'accepted'   ← הנקודה הקריטית
requireInterview && interviewSummary && date    → 'interviewed'
requireInterview && interviewDate               → 'interview_scheduled'
CV + טופס קיימים (לפי דרישות הקורס)             → 'docs_ready'
אחרת                                            → 'pending'
```

**כאן נולדת הבעיה:** ברגע שמסמנים "עבר ראיון", המועמד מקבל סטטוס `accepted` — אבל **נשאר ברשימת המועמדים לנצח**, עם תג ירוק "התקבל" + תג ירוק "עבר ראיון" (index.html:4067, 4071). זו "הנקודה הירוקה" שמציפה את הדף.

### 2.3 ההעברה לסטודנטים — `transferToStudents()` (index.html:4709)

הפעולה ידנית, לחיצה אחת לכל מועמד, ולא קורית שום דבר אם לא לוחצים.

| מה עובר | מה **הולך לאיבוד** |
|---------|---------------------|
| `name, phone, email, city` | `interviewSummary` — **סיכום הראיון** |
| `file_cv → file_cv` | `interviewDate`, `interviewResult` |
| `file_application → file_form` | `evalCommitment / Motivation / Communication / English / Acquaintance` |
| `notes` + שורת "הועבר בתאריך" | `evalScore` — הציון הממוצע |
| `courseId, year` | `applicationDate`, `acceptedDate`, `preferredArea` |
| `fromCandidate: true` | `manualSummary`, `rejectionReason`, ה-`id` המקורי |

בסוף הפונקציה: `DB.candidates = DB.candidates.filter(x => x.id !== candId)` — **הרשומה נמחקת לגמרי**.

**המשמעות:** התהליך הקיים לא רק לא מעביר את המידע — הוא גם מוחק את ההיסטוריה. אחרי העברה, המועמד נעלם מהמשפך בדשבורד (index.html:3892), מדוח המועמדים (index.html:5887), מייצוא האקסל (index.html:6529), ומלוח השנה (index.html:2918 — הראיון שלו נעלם מהלוח). לכן **הפתרון חייב להיות ארכוב ולא מחיקה.**

### 2.4 השורה בדף המועמדים — `renderCandidates()` (index.html:4023)

```
[שם]                                    [סיכום תיק] [ערוך] [מחק]
[טלפון • מייל • עיר]
[תג סטטוס] [CV] [טופס מועמדות] [ראיון: תאריך] [עבר ראיון]
[הערות]
```

שני ליקויים מהותיים:

1. **הקישורים לקבצים מזויפים.** שורות 4068-4069 מפנות ל-`getDataFolderUrl('cv')` ו-`getDataFolderUrl('application')` — **תיקיית הקורס המשותפת**, אותו קישור בדיוק לכל מועמד, ומוצג גם כשאין לו קובץ בכלל. אי אפשר לדעת מהרשימה מי הגיש CV ומי לא. לשם השוואה, שורת הסטודנט (index.html:4846-4850) פותרת `s.file_cv.folder` לתיקייה הספציפית ומסמנת קובץ חסר באדום (`.file-link.missing`).
2. **אין ציון, אין מיון, אין פעולות מרובות, אין מייל.** דף הסטודנטים מציע בחירה מרובה + סרגל פעולות (מייל קבוצתי, סימון הכנה, ייצוא, מחיקה) — index.html:4804-4821. בדף המועמדים אין כלום.

## 3. עקרונות מנחים

1. **מקור אמת יחיד.** אחרי ההמרה, כרטיס הסטודנט הוא היחיד שנערך. רשומת המועמדות הופכת לקריאה-בלבד.
2. **שום נתון לא נעלם.** לא מוחקים רשומות — מארכבים. המשפך, הדוחות ולוח השנה ממשיכים לעבוד על נתוני עבר.
3. **המידע במקום שבו מקבלים את ההחלטה.** אם צריך לפתוח כרטיס כדי לראות אם יש CV — התצוגה נכשלה.
4. **הרחבה, לא שכתוב.** כל השדות החדשים אדיטיביים; קבצי JSON וגיבויים ישנים ממשיכים להיטען.
5. **הפיכות.** לכל פעולת המרה יש `saveBeforeAction()` (ביטול) וכפתור "החזר למועמדים".

## 4. פתרון א' — המרת מועמד לסטודנט

### 4.1 תוספות למודל הנתונים

**על רשומת המועמד** (`DB.candidates[i]`):

| שדה | טיפוס | משמעות |
|-----|-------|---------|
| `converted` | boolean | `true` = הומר לסטודנט; יורד מהרשימה הפעילה |
| `convertedDate` | string (YYYY-MM-DD) | תאריך ההמרה |
| `convertedBy` | string | שם המשתמש שביצע (מ-`DB.currentUser.name`) |
| `studentId` | number | מזהה הסטודנט שנוצר — קישור דו-כיווני |

**על רשומת הסטודנט** (`DB.students[i]`):

| שדה | טיפוס | משמעות |
|-----|-------|---------|
| `candidateId` | number | מזהה רשומת המועמדות המקורית |
| `candidacy` | object | **תיק המועמדות המלא** — ראה 4.3 |

**מבנה `candidacy`:**

```js
candidacy: {
  candidateId:      12,
  applicationDate:  '2026-01-14',
  interviewDate:    '2026-02-03',
  interviewResult:  'passed',
  interviewSummary: 'מוטיבציה גבוהה, ניסיון קודם בגיוס...',
  preferredArea:    'גיוס ומיון',
  acceptedDate:     '2026-02-03',
  evalScore:        88,
  evals: {
    commitment: 'גבוה', motivation: 'גבוה',
    communication: 'בינוני', english: 'גבוה', acquaintance: 'נמוך'
  },
  manualSummary:    '',
  convertedDate:    '2026-02-03',
  convertedBy:      'ד"ר יריב איצקוביץ'
}
```

**נימוק לאובייקט מקונן:** מונע התנגשות שמות עם שדות הסטודנט הקיימים (ל-`student.interviews` כבר יש משמעות אחרת — מספר ראיונות אצל מעסיקים), שומר על הכרטיס נקי, ומאפשר תצוגה גנרית של הסקשן.

### 4.2 מתי מתרחשת ההמרה — טריגר

**ברירת מחדל: המרה מיידית בשמירה.**

ב-`saveCandidate()` (index.html:4389), אחרי חישוב הסטטוס:

```
אם status הפך ל-'accepted' והמועמד עדיין לא converted:
  → הצג דיאלוג: "‏{שם} עבר/ה את הראיון. להעביר עכשיו לרשימת הסטודנטים?
                  תיק המועמדות (טופס, קו״ח, סיכום ראיון) יעבור לכרטיס הסטודנט."
     [כן, העבר] (ברירת מחדל)   [לא כרגע]
  → "כן"  : convertCandidateToStudent(id) + טוסט הצלחה עם קישור "פתח כרטיס סטודנט"
  → "לא"  : המועמד נשאר בדף המועמדים בסטטוס "התקבל — ממתין להעברה"
```

**מנגנון השלמה** — באנר קבוע בראש דף המועמדים כשקיימים מועמדים `accepted && !converted`:

> ⚡ **3 מועמדים עברו ראיון וממתינים להעברה לסטודנטים** &nbsp; [העבר את כולם] [הצג רק אותם]

כך גם מי שדחה את הדיאלוג לא נשאר עם זנב, וגם אין המרה כפויה.

**הגדרה בקורס:** תיבת סימון "העבר אוטומטית לסטודנטים בסיום ראיון מוצלח" (ברירת מחדל: מסומן), יחד עם `requireCV / requireApplication / requireInterview / requirePrep` הקיימות ב-`getCourseReqs()` (index.html:1746). כשמסומן — ההמרה קורית בלי דיאלוג, עם טוסט + אפשרות ביטול.

### 4.4 מה קורה לרשומת המועמד

**היא נשארת.** מסומנת `converted: true` ומקבלת:

* אינה מוצגת ברשימת המועמדים הפעילה (מסנן ברירת מחדל).
* מוצגת בתצוגת **ארכיון** (צ'יפ "הומרו לסטודנטים" במשפך + מסנן ייעודי) — בעיצוב מעומעם, עם תג "🎓 סטודנט" וכפתור **"פתח כרטיס סטודנט"**.
* עריכה חסומה: `editCandidate()` על רשומה מומרת פותחת תצוגת קריאה-בלבד עם הודעה: *"המועמד/ת הומר/ה לסטודנט/ית — יש לערוך בכרטיס הסטודנט"* + כפתור מעבר.
* פעולת **"החזר למועמדים"** (Undo): מוחקת את הסטודנט (בכפוף לאישור, ורק אם אין לו נתוני השמה — `acceptedOrg`/`submitted`/`hoursReported`), מנקה `converted/studentId`, ומחזירה לרשימה.

### 4.5 מיגרציה לנתונים קיימים

רצה פעם אחת ב-`loadFromStorage()` (index.html:1378) ואחרי טעינה מהענן, מוגנת בדגל `DB.settings.candidateMigration === 'v1'`. גם זמינה ידנית מהגדרות: **"סנכרון מועמדים ↔ סטודנטים"**.

```
לכל מועמד c שבו c.converted === undefined:
  1. חפש סטודנט תואם באותו courseId + year לפי סדר:
       א. email זהה (case-insensitive)
       ב. 9 ספרות אחרונות של הטלפון
       ג. שם מנורמל זהה (trim + כיווץ רווחים)
  2. אם נמצא סטודנט s:
       - c.converted = true;  c.studentId = s.id;  c.convertedDate = c.acceptedDate || היום
       - s.candidateId = c.id
       - s.candidacy = מולא מ-c  (רק שדות ריקים — לא דורסים מידע קיים)
       - s.file_cv   ||= c.file_cv
       - s.file_form ||= c.file_application
  3. אם לא נמצא ו-c.status === 'accepted':
       - נשאר מועמד פעיל, מסומן "ממתין להעברה" ומופיע בבאנר
  4. אחרת: c.converted = false
```

בסיום מוצג דוח: *"סונכרנו 14 מועמדים לסטודנטים קיימים · 3 ממתינים להעברה · 27 מועמדים פעילים"*.
לפני הריצה — `saveBeforeAction()`, כך שכפתור "↶ ביטול" מחזיר הכל.

### 4.7 מקרי קצה

| תרחיש | התנהגות נדרשת |
|---|---|
| מועמד עבר ראיון וכבר קיים סטודנט באותו שם | לא ליצור כפילות — לזהות, למזג את תיק המועמדות לסטודנט הקיים, ולהציג "מוזג לסטודנט קיים" |
| שינוי "עבר ראיון" ל"לא עבר" אחרי המרה | חסום — נדרש קודם "החזר למועמדים" |
| מחיקת סטודנט שהומר | הרשומה במועמדים חוזרת אוטומטית לפעילה (ניקוי `converted`) + טוסט הסבר |
| מועמד שנדחה (`rejected`) | **נשאר בדף המועמדים** — הוא מועמד, לא סטודנט. ניתן להסתירו במסנן |
| קורס ללא ראיון (`requireInterview: false`) | ההמרה מופעלת ידנית מכפתור "העבר לסטודנטים" מסטטוס `docs_ready` |

| רכיב | התנהגות |

**שורה 2 — פרטי קשר**
`טלפון • מייל • עיר • תחום מבוקש` — הטלפון והמייל כקישורי `tel:`/`mailto:` (כמו ב-`showSearchResultInfo`, index.html:6058).

**שורה 3 — תגים (הליבה של השדרוג)**

| תג | מצבים | צבע |
|---|---|---|
| סטטוס | 6 סטטוסים קיימים | לפי `CAND_STATUS_BADGE` (4021) |
| **קו״ח** | `✓ קו״ח` (קישור לתיקייה הספציפית) / `✗ קו״ח חסר` / `קו״ח: לא נדרש בקורס` / `לא רלוונטי` | ירוק / **אדום** / אפור / אפור |
| **טופס מועמדות** | אותם 4 מצבים | ירוק / **אדום** / אפור / אפור |
| ראיון | `📅 ראיון 03/02/26` / `⏰ ראיון מחר` / `⚠ עבר תאריך ללא תוצאה` | כחול / כתום / אדום |
| תוצאה | `✓ עבר` / `✗ לא עבר` | ירוק / אדום |
| **ציון** | `ציון 88` — רק אם קיים | ≥85 ירוק · 70-84 כתום · <70 אפור |
| **ותק** | `הוגש לפני N ימים` — רק אם >7 ימים ואין ראיון | כתום; >14 ימים אדום |

**זהו התיקון המרכזי:** במקום קישור אחיד לתיקיית הקורס, כל תג קובץ נגזר מ-`c.file_cv` / `c.file_application` בפועל, מפנה ל-`getDataFileFolderUrl(file.folder)`, ומתחשב ב-`getCourseReqs()`. אותה לוגיקה בדיוק שכבר עובדת בשורת הסטודנט (index.html:4845-4850) — שימוש חוזר, לא המצאה מחדש.

**שורה 4 — מיני-הערכה**
5 קריטריונים כנקודות: `●` גבוה (ירוק) · `◐` בינוני (כתום) · `○` נמוך (אפור) · ללא סימון = לא מולא. מוצג רק אם מולא לפחות קריטריון אחד. `title` על כל אחד לקריאת מסך.

**שורה 5 — הרחבה**
`▾ הצג סיכום ראיון` (`<details>`) — הטקסט המלא של `interviewSummary`, קטוע ל-3 שורות עם "הצג הכל". מוצג רק כשקיים תוכן. מטרתו: **גישה לסיכום הראיון בלי לפתוח את הכרטיס.**

**שורה 6 — הערות**
`notes` בעיצוב הקיים; אם `rejectionReason` קיים — תיבה אדומה נפרדת "סיבת דחייה: ...".

## 9. קריטריוני קבלה

**בעיה א' — הפרדה**

1. סימון "עבר ראיון" ושמירה → המועמד יורד מרשימת המועמדים ומופיע ברשימת הסטודנטים, בלחיצה אחת.
2. בכרטיס הסטודנט החדש קיימים: קו״ח, טופס מועמדות, תאריך ראיון, תוצאה, ציון, 5 קריטריוני הערכה, וסיכום הראיון המלא.
3. סך `מועמדים פעילים + מומרים` = מספר המועמדים לפני השינוי. **אפס אובדן רשומות.**
4. משפך המועמדים בדשבורד מציג את המומרים ואת שיעור ההמרה.
5. ראיון של מועמד שהומר עדיין מופיע בלוח השנה.
6. הרצת המיגרציה על מסד קיים לא יוצרת סטודנטים כפולים.
7. "↶ ביטול" מחזיר המרה שבוצעה בטעות.

**בעיה ב' — עושר תצוגה**

8. מהשורה בלבד, ללא כניסה לכרטיס: פתיחת קו״ח, פתיחת טופס המועמדות, קריאת תאריך הראיון, קריאת הציון, קריאת סיכום הראיון.
9. מועמד ללא קו״ח מסומן באדום ונמצא במסנן "חסר CV".
10. קישור הקובץ מפנה לתיקייה של הקובץ עצמו — לא לתיקיית הקורס הכללית.
11. ניתן לבחור מספר מועמדים ולבצע: מייל קבוצתי, העברה לסטודנטים, ייצוא, מחיקה.
12. הדף תקין במובייל — אין גלישה אופקית.

## 10. סיכונים והפחתתם

| סיכון | הפחתה |
|---|---|
| מיגרציה תיצור סטודנטים כפולים | התאמה לפי מייל→טלפון→שם; `saveBeforeAction()` לפני הריצה; דוח לפני החלה; דגל חד-פעמי |
| שני מכשירים מריצים מיגרציה במקביל (Supabase realtime) | דגל `candidateMigration` נשמר ב-snapshot; המכשיר השני מזהה ולא מריץ שוב |
| משתמש יחפש מועמד שהומר ולא ימצא | חיפוש גלובלי מחזיר אותו כ"מועמד (הומר)" ופותח את כרטיס הסטודנט; צ'יפ ארכיון בולט |
| שורה עמוסה מדי | תגים מותנים בלבד — ריק לא מוצג; הערכה וסיכום מקופלים |
| ייבוא JSON ישן ידרוס שדות חדשים | הייבוא ממזג ולא דורס; שדות חסרים מקבלים ברירת מחדל |

## נספח: השוואה לפני/אחרי

**שורת מועמד — היום**

```
דנה כהן                                    [סיכום תיק] [ערוך] [מחק]
052-1234567 • dana@x.com • פתח תקווה
[התקבל] [CV] [טופס מועמדות] [ראיון: 2026-02-03] [עבר ראיון]
```
`CV` ו`טופס מועמדות` — אותו קישור לכל המועמדים, לתיקיית הקורס. מופיעים גם למי שלא הגיש דבר. אין ציון, אין ותק, אין סיכום ראיון, אין בחירה מרובה. והמועמד הזה — שכבר עבר ראיון — לא אמור להיות ברשימה בכלל.

  [רואיין] [✓ קו״ח] [✓ טופס מועמדות] [📅 ראיון 03/02/26] [ציון 88] [הוגש לפני 21 ימים]
  מחויבות ● מוטיבציה ● תקשורת ◐ אנגלית ● היכרות ○
